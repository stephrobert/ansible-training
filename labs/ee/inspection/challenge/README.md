# Somebody picked an EE because it was first in the search results

## The situation

The project standardised on an Execution Environment last quarter, chosen the way
these things usually are: someone found an image name in a blog post and it
worked. It weighs two gigabytes, ships collections nobody uses, and still lacks
the one your playbooks need, which a colleague now installs at run time inside the
container, quietly defeating the whole point. Before you build your own, you need
to be able to say what is actually inside these things.

Your mission, from the project directory:

1. Script the inspection of an EE: **list the collections it embeds**, the
   `ansible-core` version it carries, its system packages and its real size.
2. Run that inspection across **three** official EEs, one aimed at authoring, one
   at a controller, one deliberately minimal, and compare the results.
3. Read a module's documentation **as the EE sees it**, since what is documented
   inside the image is what your playbook can actually call.
4. Turn the comparison into a **choice per use case**: which EE for training,
   which for a controller, which for lean production, and why.

The full method is in the companion guide:
https://www.stephane-robert.info/docs/infra-as-code/gestion-de-configuration/ansible/execution-environments/lookup-doc/ (in French)

## 🎯 Challenge : compare 3 Execution Environments, with proof

### ✅ Mission

Write `inspect.sh` (delivered as a skeleton at the lab root), run it,
and produce a factual comparison report.

| Deliverable | Expectation |
| --- | --- |
| `inspect.sh` | completed (no more `???`), executable, valid bash syntax. Inspects the 3 EEs `community-ansible-dev-tools`, `awx-ee`, `community-ee-minimal` with podman and ansible-navigator |
| `inspect-output/comparison.md` | generated by YOUR script: a Markdown table with, for each of the 3 EEs, the observed ansible-core version and the image size |

The report must come from an actual run of the script (`./inspect.sh`),
not from a copy-paste: the observed versions change with the
`latest` tags, which is precisely the point of the inspection.

### 🧩 Stuck?

```bash
dsoxlab hint ee-inspection
```

Hints are progressive and **cost points**: the first one points you in the
right direction, the last one unblocks you.

### 🚀 Launch

```bash
cd labs/ee/inspection/
./inspect.sh
cat inspect-output/comparison.md
```

### 📓 Command log

Record in `challenge/solution.sh` the commands you ran. This log
must exist for pytest to run:

```bash
chmod +x challenge/solution.sh
```

### 🧪 Validation

```bash
pytest -v labs/ee/inspection/challenge/tests/
```

Pytest checks your script (real bash syntax, tools used, 3 EEs
covered) and the factual content of the generated report. It does not pull the
images itself (several GB): it is your run that produces the
report.

### 🧹 Reset

```bash
dsoxlab clean ee-inspection
```
